## What is GhostDocs?

Every software proejct accumulates knowledge over time. Some decisions go undocumented, old instructions become outdated, and important context gets lost.

`GhostDocs` helps maintainers investigate these potential knowledge gaps by analysing repository content through a combination of repository scanning, rule-based analysis, and locally running AI models.

Its goal is to answer three questions:

- What documentation does this repository have?
- What important knowledge has this repository lost, forgotten, or failed to document?
- How healthy and maintainable is its existing documentation?

> What important knowledge has this repository lost, forgotten, or failed to document?

**Unlike traditional documentation linters**, `GhostDocs` focuses on understanding potential gaps in project knowledge rather than checking Markdown formatting or broken links.

## What It Does

- Scans repositories to discover relevant project files and documentation.
- Provides an overview of repository documentation and its structure.
- Identifies potential knowledge gaps using rule-based analysis.
- Evaluates documentation health using repository findings.
- Uses local AI analysis through Ollama to investigate findings and their context.
- Generates Markdown reports organized into five sections:
  - 📖 Documentation Overview
  - 👻 Lost Knowledge
  - 🕯️ Ghost Sightings
  - 🩺 Documentation Health
  - 🎃 Resurrection Plan

`GhostDocs` is designed to help maintainers reflect on what their projects might be missing and decide what deserves further investigation.

## Quick Start

Try `GhostDocs` on your own repository in a few steps.

### 1. Prerequisites

Make sure you have:

- Python 3.12 or newer
- pipx
- Ollama installed and running locally
- An Ollama model downloaded locally (default: gemma4:e4b)

### 2. Install `GhostDocs`

Install GhostDocs directly from GitHub:

```bash
pipx install git+https://github.com/yuka-with-data/GhostDocs.git
```

### 3. Analyze a Repository

Navigate to the repository you want to analyze:

```bash
cd path/to/your-project
```

Run `GhostDocs`:

```bash
ghostdocs .
```

### 4. Explore the Report

`GhostDocs` analyzes the repository and generates a Mardown report containing five sections.

## How It Works

`GhostDocs` combines repository scanning, rule-based analysis, and local AI to generate a documentation analysis report.

1. Scan: Discover relevant files in the target repository.
2. Analyze: Identify potential knowledge gaps and unfinished business.
3. Build context: Prepare repository findings for AI analysis.
4. Investigate: Use Ollama to examine the findings and their supporting context.
5. Generate: Produce a Markdown report with observations and suggested actions.

>[!NOTE]
> GhostDocs uses version-controlled prompt templates stored in `src/ghostdocs/prompts/`. These templates are publicly available for transparancy, inspection, and customization.

## Usage

`GhostDocs` accepts a repository path as its positional argument.

```bash
# Analyze the current repository.
ghostdocs .

# Analyze a different repository.
ghostdocs path/to/project

# Save the report as a Markdown file.
ghostdocs . --output reports/ghost-report.md

# Save to a nested directory (created automatically if needed).
ghostdocs . --output output/analysis/ghost-report.md

# Use a different installed Ollama model.
ghostdocs . --model llama3.2

# Display available CLI arguments.
ghostdocs --help
```

### CLI Options

| Argument       | Required | Description                                    |
| -------------- | -------- | ---------------------------------------------- |
| `project_path` | Yes      | Path to the repository to analyze.             |
| `--output`     | No       | Path to save the generated Markdown report.    |
| `--model`      | No       | Ollama model to use. Defaults to `gemma4:e4b`. |
| `--help`       | No       | Display available commands and options.        |

If `--output` is omitted, the report is printed directly in the terminal.

## Known Limitations (Alpha)

`GhostDocs` is an early-stage project primarily designed for small to medium-sized software repositories.

### Repository Size (Estimated Guideline)

| Size | Approximate File Count |
|---|---:|
| Small | 1–100 |
| Medium | 100–500 |
| Large | 500–2,000 |
| Very Large | 2,000+ |

These are preliminary testing guidelines, not enforced limits. Performance depends on repository content, file sizes, available system resources, and the selected Ollama model.

### Context and Processing Contraints

- Context Budget: Repository files are added until a fixed character budget is reached. Files beyond that limit may not be analyzed.
- Context Window: The selected Ollama model has a limited context capacity, which affects how much repository content it can process at once.
- Context Budget vs. Context Window: `GhostDocs` limits the repository content prepared for analysis, while Ollama's context window determines the model's available context capacity.

### AI and Analysis Limitations

- AI Accuracy: Findings and recommendations depend on the available repository content and the selected Ollama model. Results may be incomplete or inaccurate.
- No External Verification: `GhostDocs` analyzes supplied repository content and does not independently verify findings against external sources.
- No Automatic Changes: `GhostDocs` generates reports but does not modify repository files or resolve identified issues.
- Prompt Injection: Safeguards are included, but they cannot guarantee complete protection against malicious instructions embedded in repository content.

Treat generated reports as suggestions for maintainer review, not definitive assessments of a project.
